# Assumptions and unresolved implementation boundaries

- Project confirmations contain the concrete `$` dates, years, distances, species and similar parameters in Annex I. The supplied canonical profile has none of these records; therefore the policy validates code membership and a per-parcel confirmation of compliance, rather than inventing dates.
- Annex I is captured as a complete closed code list. The operational prose of every assigned code remains binding through the project confirmation. A future profile with typed event/operation records can support per-code machine verification.
- Annex J's matrix is retained as the source rule. The executable checks implement the explicit SA01-care dependency and AA06 exclusion; chapter-level matching should be extended when a parcel can carry more than the current project-code list.
- The 12 August 2026 drought exception is date-specific and overrides only fixed use dates from that date; it does not amend project confirmations.
