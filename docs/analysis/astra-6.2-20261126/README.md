## Attempts and validation

One measure passed on the first model attempt. A further 23 passed on the second. Two needed a third attempt, `o6_10` and `o6_18`. The [campaign ledger](campaign.json) lists every local start, budget refusal, timeout, source-validation result and the selected result per measure. Each final candidate has its OPA report, grounding report, profile proposals, coverage ledger and inventory alongside its rules and tests.

The original cloud generation of `o6_15` had a reported generator exit code of zero. Its workspace and finalization outcome could not be recovered. An independent local replacement used the frozen inputs and the campaign identifier required by the source references. The counts above cover the local executions. [Campaign issue and dated decisions](https://github.com/ghinta/oepul-rule-lab/issues/115#issuecomment-7171939639)

Before the 26 November budget change, each new model start required at least 50% remaining in the provider’s weekly window. The later approval lowered the start threshold to 5%. A reading of 5% or less during generation triggered a controlled stop under both approvals. The 49% reading before the first local generation of `o6_5` is preserved as a preflight refusal. The original one-hour timeout of `o6_10` is also recorded. Each resumed generation used a separate workspace based on its predecessor. A model correction received the prior workspace and the validator findings.

## Reproducing the evidence

The primary sources, canonical profile and original instruction template were pinned at [the input revision](https://github.com/ghinta/oepul-rule-lab/tree/7df5585c563428af178ec4d27f4276c3448c2e57). The source hashes for all 26 measures matched the selected historical Luna and Opus source sets. The [first runner](https://github.com/ghinta/oepul-rule-lab/commit/bdc5d49b06d4934aed87661ccdaab9f4d1a691d4) and [updated runner](https://github.com/ghinta/oepul-rule-lab/commit/75d08892a14f4ab1bba163366ba9b69a2f3fabe5) supplied the budget amendment. Each attempt records its actual model, threshold and start reading. The local runner requested `gpt-6.2-astra` with high reasoning effort in `discover` mode.

Within each published run, `evidence/<step>/run.json` contains the original metadata for that execution step. For a submitted prompt, `evidence/<step>/prompt/` holds the prepared prompt, budget amendment, effective input and hash record. Original metadata retains the logical paths used by the runner. Its `raw/prompts/<attempt>/` references resolve in the published `evidence/<step>/prompt/` directory, and `raw/parent-run.json` resolves to `evidence/<step>/parent-run.json`. The frozen instructions are in `workspace/AGENTS.md`. Failed finalizations include their validation diagnostics at the corresponding step.

The original inventory covers the generated files, the staged source pack and the private event transcript. Each local inventory entry was verified against its size and SHA-256. Source PDFs can be recovered via the versioned source paths in `run.json`. Page-marked extraction files and event transcripts stay in the local archive. The public inventory retains their checksums.
